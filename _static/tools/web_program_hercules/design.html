1 · 概述与决策落实

基于 web_download_hercules 的协议与传输层，特化批量生产自动化量产网页。 本版（v3.1）为已实施版本，在 v3.0 基础上追加：多文件虚拟单一文件烧写、占用空间重叠检测、烧录地址 0x100 对齐、触发稳定基线（修复 RXD 默认电平伪触发）、配置授权前置、量产中文件表锁定等（见下方 v3.1 实施摘要）。

✅ v3.0 实施摘要：
  • GET_STATUS 布局 / 数据大小：确认（payload 从 offset 4，packed 7 字节）
  • 状态动作时序：边沿动作电平保持，直到 VREF 变化或满足下次触发
  • 重试：最小命令包重试优先，失败回退整文件烧写；命令级 3s 超时；4 项统计口径
  • 重试计数：块级与文件级双计数器独立（上限均 retryCount），块级成功/彻底失败后清零
  • VREF：仅 vref_mv_valid 判定触发；vref_mv 只做 UI 电压显示；严格 0→1 上升沿（首帧仅建立基线，不触发）
  • 触发方式新增间隔触发：烧录完成后等 N 秒（1-10s，默认 3s）自动烧下一片（§4.2）
  • 整片失败：记录即可，无停机策略（触发 + 状态输出已满足自动化）
  • 状态输出：电平保持，SRST 为普通 IO 直通 0/1（无反相），忙电平→成功/失败翻转→下一片恢复（§5）
  • 实时状态：新增进度条 PROG（烧录中青蓝 / 成功绿 / 失败红 / 重试琥珀，pass/fail 保持至下次烧录）+ SESSION 徽章
  • UI：配置卡片量产中灰化锁定；开始按钮已连接+有文件才可用（绿色），点击后灰化
  • 容量校验：PROBE 后若烧录地址总范围 maxEnd > capacity，直接按错误处理（§7.1）
  • 多工位：预留接口，先单工位；TXD 接管：退出量产 RELEASE
  • 部署浏览器：必须 Chrome / Edge（WebUSB 硬性要求），详见 §10
✅ v3.1 实施摘要：
  • 配置授权前置：必须先获得目录授权才能自动导入/导出配置；「📁 授权目录（内置固件及配置）」授权后显示目录名；导出/载入配置按钮仅授权后可用（灰化）（§9.3）
  • 文件表自定义选择控件：左侧「📁 选择文件 / 🔄 更换」按钮 + 文件名文本（原生 file input 无法 JS 赋值，修复载入配置后左侧显示空白）
  • 移除烧写选项中的全局 Auto Cut ACF：ACF 头裁剪由文件表每行 Cut ACF（默认勾选）决定（§7）
  • 地址 0x100 对齐：所有文件烧录地址必须 0x100 对齐，未对齐文件表红色告警并禁止开始量产（§7.2）
  • 占用空间重叠检测：多文件实际烧写区间（ACF+CutACF 排除注释头）两两检测重叠，重叠红色告警并禁止开始量产（§7.2）
  • 多文件虚拟单一文件烧写：按地址升序，addr=首个文件地址、data_pos=相对头部偏移、full_length=最大偏移-基地址、缝隙跳过；满足下载器完成判定与 Auto Run（§7.3）；含 slice_pos 修复（数据切片用文件内偏移，命令字段与切片索引分离）
  • 触发稳定基线：边沿检测前连续 3 帧电平一致才作为基线，修复 RXD 默认高（上升沿）/默认低（下降沿）时接管瞬态造成的点击开始即触发伪边沿（§4.1）

3 · 响应格式与状态解析（已确认）

3.1 统一响应布局

[0]  = 0x90                      vendor id
[1]  = subcmd                    子命令回显
[2]  = cmdSts (DAP_OK = 0)       命令层状态
[3]  = subSts (RESP_OK = 0)      子命令层状态
[4:] = payload                   数据区  ✅ 已确认

3.2 GET_STATUS 响应解析（packed 7 字节，已确认）

struct hercules_dap_vendor_status_t {   // VSF_CAL_PACKED
    int32_t vref_mv;        // [4..8]   偏移4, 4字节  (单位 mV)   → 仅 UI 显示
    bool    vref_mv_valid;  // [8]      偏移8, 1字节  (VREF 稳定) → 触发判定依据
    bool    rxd_logic_level;// [9]      偏移9, 1字节  (RXD 电平)
    bool    key_mode;       // [10]     偏移10,1字节  (模式键)
}
// JS 解析
const v = new DataView(resp.buffer, resp.byteOffset + 4, resp.byteLength - 4);
const status = {
    vrefMv:    v.getInt32(0, true),   // 偏移 4
    vrefValid: v.getUint8(4) !== 0,   // 偏移 8
    rxdLogic:  v.getUint8(5) !== 0,   // 偏移 9
    keyMode:   v.getUint8(6) !== 0    // 偏移 10
};

3.3 命令请求格式

get_status()            → [0x90, 0x04]
takeover_txd_rxd()      → [0x90, 0x02]
release_txd_rxd()       → [0x90, 0x03]
output_txd_srst(t,s)    → [0x90, 0x05, txd_level(0/1), srst_level(0/1)]

4 · 触发检测（6 种方式）

~100ms 轮询 GET_STATUS，按配置模式判定。除手动与间隔外均为边沿事件。 v3.1：边沿检测前先建立"稳定基线"（连续 3 帧、约 300ms 电平一致），期间不触发； 避免 TAKEOVER/上电瞬态在 RXD 默认高（上升沿）或默认低（下降沿）电平下产生伪边沿导致点击开始即触发。 VREF 触发只看 vref_mv_valid，且为严格 0→1 上升沿：稳定基线后必须检测到 VREF 从无效→有效（掉电再上电）才触发； vref_mv 仅用于 UI 实时显示。prev 状态跨片保持（_triggerPrev），支持连续量产换片。

模式判定条件（边沿）来源
key-risingkeyMode 0 → 1模式键按下
rxd-risingrxdLogic 0 → 1RXD 上升沿
rxd-fallingrxdLogic 1 → 0RXD 下降沿
vref-risingvrefValid 0 → 1（严格，首帧不触发）VREF 掉电再上电
manual网页按钮点击人工
auto-timer烧录完成后等 N 秒自动触发间隔触发（1-10s，默认 3s）

4.1 边沿检测（v3.1：稳定基线 + 严格边沿 + 跨片保持）

// 阶段1: 建立稳定基线 (连续 3 帧电平一致, 期间不触发), 吸收 TAKEOVER/上电瞬态
const STABLE_FRAMES = 3;
let prev = null, stable = 0;
while (this.running) {
    const s = await getStatus();
    if (!prev) { prev = { key: s.keyMode, rxd: s.rxdLogic, vref: s.vrefValid }; stable = 1; }
    else if (prev.key===s.keyMode && prev.rxd===s.rxdLogic && prev.vref===s.vrefValid) {
        if (++stable >= STABLE_FRAMES) break;              // 基线稳定
    } else { prev = { key: s.keyMode, rxd: s.rxdLogic, vref: s.vrefValid }; stable = 1; }
    await sleep(100);
}
// 阶段2: 边沿检测 (只有从稳定基线发生跳变才触发, prev 跨片保持)
while (this.running) {
    const s = await getStatus();
    if (mode === 'vref-rising') {                          // 严格 0→1: 基线 false, 掉电再上电才触发
        if (prev.vref === false && s.vrefValid === true) { this._triggerPrev = {...}; return; }
    } else if (mode === 'key-rising' && prev.key === false && s.keyMode === true) { ...return; }
    else if (mode === 'rxd-rising' && prev.rxd === false && s.rxdLogic === true) { ...return; }
    else if (mode === 'rxd-falling' && prev.rxd === true && s.rxdLogic === false) { ...return; }
    prev = { key: s.keyMode, rxd: s.rxdLogic, vref: s.vrefValid };
    this._triggerPrev = prev;
    await sleep(100);
}

4.2 间隔触发 auto-timer

  • 间隔秒数：下拉框 1s ~ 10s，步进 1s，默认 3s（内嵌于"间隔触发"选项右侧，未选中时禁用）
  • 开始量产首次立即烧第一片（_autoFirst 标记）；之后每片完成（无论成败）等待 N 秒自动触发下一片
  • 等待采用 100ms 分片循环，点停止可随时中断
  • 进度条在间隔等待期间保持上片结果（绿/红），下一片开始恢复 0% 蓝色
if (mode === 'auto-timer') {
    if (this._autoFirst) { this._autoFirst = false; return; }        // 首次立即
    const ms = (this.cfg.trigger.autoInterval || 3) * 1000;
    const steps = Math.max(1, Math.ceil(ms / 100));
    for (let i = 0; i < steps && this.running; i++) await sleep(100); // 可被 stop 中断
    return;
}

5 · 状态输出（电平保持）

TAKEOVER_TXD_RXD 接管引脚后，网页用 OUTPUT_TXD_SRST 输出。 关键：SRST 为普通 IO，参数直通 0/1（写 0=低、写 1=高，无反相）。 时序：烧录前及烧录时保持"忙电平"→ 成功/失败翻转为结果电平 → 下一片触发烧录恢复忙电平。 结果电平保持，不回空闲，产线 PLC 可稳定读取。

状态TXD（按成功动作）SRST（按失败动作）说明
忙（烧录前/中）rise→0 / fall→1rise→0 / fall→1signalReady/signalBusy 共同设置
成功动作rise→1 / fall→0保持pass_txd_rise / pass_txd_fall / none
失败动作保持rise→1 / fall→0fail_srst_rise / fail_srst_fall / none
 
// 状态输出（电平保持模型，0/1 直通无反相）
// _signalBusyLevels: 忙电平（烧录前/中保持）——上升沿→低(0)，下降沿→高(1)
async _signalBusyLevels() {
    let t = null, s = null;
    if (passAction === 'pass_txd_rise') t = 0;
    else if (passAction === 'pass_txd_fall') t = 1;
    if (failAction === 'fail_srst_rise') s = 0;
    else if (failAction === 'fail_srst_fall') s = 1;
    if (t === null && s === null) return;          // 全部无动作: 不改变引脚
    await outputTxdSrst(t, s);
}
signalReady() { if (enable) await _signalBusyLevels(); }   // 烧录前
signalBusy()  { if (enable) await _signalBusyLevels(); }   // 烧录中 / 下一片恢复忙电平
// 成功: 仅翻转 TXD 为成功电平 (rise→1, fall→0), SRST 保持
signalPass()  { const t = a === 'pass_txd_rise' ? 1 : a === 'pass_txd_fall' ? 0 : null; if (t!==null) await outputTxdSrst(t, null); }
// 失败: 仅翻转 SRST 为失败电平 (rise→1, fall→0), TXD 保持
signalFail()  { const s = a === 'fail_srst_rise' ? 1 : a === 'fail_srst_fall' ? 0 : null; if (s!==null) await outputTxdSrst(null, s); }
// outputTxdSrst(t, s): null 表示保持该引脚当前电平（内部 _outTxd/_outSrst 跟踪）

📌 结果电平保持到下一片触发；failAction=none 或 passAction=none 时不改对应引脚。 退出量产 RELEASE_TXD_RXD 恢复。

6 · 超时 / 重试 / 统计

6.1 命令级超时（已决策）

单个命令 3 秒无响应判定超时，超时即按重试机制重试（见 6.2）。触发等待本身不设超时，一直等到触发为止。

6.2 重试机制（已决策 · 双计数器独立）

两个独立计数器，上限均为 retryCount（0-9，默认 2），互不影响：

① 块级重试（最小命令包）
  • 烧写按 256B/包 分块发送，某块失败/超时 → 仅重发该命令包
  • 计数器 blockRetry：0..retryCount
  • 该块成功 → 清零（下一个块从 0 重新开始）
  • 该块重试耗尽 → 清零（升级为整文件回退）
② 整文件回退
  • 块级彻底失败（或需重新擦除）→ 重新执行整个文件烧写过程
  • 计数器 fileRetry：0..retryCount
  • 整文件成功 → 清零（进入下一个文件）
  • 整文件重试耗尽 → 清零（该片判失败）
// 双计数器独立重试伪代码
let fileRetry = 0;
for (const f of files) {
    let done = false;
    while (!done) {
        let blockRetry = 0;                                  // 每次整文件尝试，块级计数从 0 开始
        let pos = 0, ok = true;
        while (pos < fileSize(f)) {
            const resp = await sendBlock(f, pos);            // 发送单个 256B 命令包
            if (!respOk(resp)) {
                blockRetry++;
                if (blockRetry > retryCount) { ok = false; break; }   // 块级耗尽 → 整文件回退
                continue;                                     // 块级重试：仅重发该包（成功则自然清零）
            }
            blockRetry = 0;                                   // 块成功 → 清零
            pos += 256;
        }
        if (ok) { stats.burn... ; done = true; break; }       // 整文件成功
        fileRetry++;                                          // 整文件回退
        if (fileRetry > retryCount) { stats.fail...; done = true; }  // 文件级耗尽 → 该片失败
    }
}

块级与文件级计数独立：块级成功/彻底失败后清零，文件级成功/彻底失败后清零。 两个计数器的失败均计入"含重试失败次数"（§6.3）。

6.3 统计口径（已决策，4 项）

指标定义口径
总烧录数进入烧写流程的片数不含重试
总成功数烧写成功的片数不含重试
总失败数烧写失败的片数（重试耗尽后判失败）不含重试
含重试失败次数所有重试动作（块级 + 文件级）累计失败次数含重试

关系：总烧录数 = 总成功数 + 总失败数（均不含重试）；重试失败次数为独立累计。

7 · 分布式文件与偏移地址

文件表每个文件独立起始地址。烧写地址 = 文件起始地址 + 文件内部头偏移（ACF 注释头 / 芯片头 +8/+8+64）。 

files: [
  { name: "boot.bin",  addr: 0x000000, cutAcf: false },
  { name: "app.acf",   addr: 0x008000, cutAcf: true  },
  { name: "calib.bin", addr: 0x3F0000, cutAcf: false }
]

erase / verify 全局强制使能（见 §6 / §8），文件表不再逐文件配置擦除/校验开关。 复用 getFlashWriteStartPos / getChipWriteStartPos / dapTryFlashWrite(addr)。

7.1 容量校验（PROBE 后强制，已决策）

PROBE 后从 common 获取芯片实际 Flash 容量 capacity（字节）。 若烧录的数据地址总范围超出容量，直接按错误处理（该片失败，不进入烧写）。

烧录范围末端 = max( 文件起始地址 addr + 实际写入长度 ) 
// 容量校验伪代码（PROBE 成功后、开始烧写前执行）
// capacity: 芯片 Flash 容量（字节，common.getUint32(8)）
// writeLen(f): 该文件实际写入长度（ACF/芯片头裁剪后 byteLength）
const maxEnd = files.reduce((m, f) => Math.max(m, f.addr + writeLen(f)), 0);
if (maxEnd > capacity) {
    return error(`Flash capacity insufficient: need ${maxEnd}B, chip has ${capacity}B`);
}
// chip_write 单文件场景：writeLen(file) > capacity 同样判错

📌 校验基于裁剪后的实际写入长度（ACF 注释头 / 芯片头偏移后的数据），地址范围取所有文件的并集末端。

7.2 地址对齐与占用空间重叠检测（v3.1）

每个文件的烧录地址必须按 0x100 对齐（addr % 0x100 == 0），未对齐时文件表行内红色告警且禁止开始量产。 多文件载入时自动检查各文件实际烧写占用区间 [addr, addr + 写入长度) 是否相互重叠； .acf 且 Cut ACF 时，头部（满足 CUT ACF 算法的指定长度，即注释头偏移）从占用计算中排除：写入长度 = 文件总长 − 注释头偏移。 未加载文件不参与重叠检测。 若重叠：文件表对应行显示红色告警「⚠ 与「xxx」地址重叠」，且禁止开始量产（开始按钮灰化 + startRun 拦截）。

7.3 多文件虚拟单一文件烧写（v3.1）

多文件在地址空间不重叠的前提下，被视作一个单一虚拟文件烧写：

  • 按地址升序烧写，基地址 baseAddr = 首个文件地址（单文件时即该文件地址，命令与原有行为完全一致）
  • 每块 data_pos = 文件地址 + 文件内偏移 − baseAddr（首块 data_pos == 0，触发下载器 VDDQ/EFUSECLK 设置）
  • full_length = 最大偏移 − 基地址（max(addr + 写入长度) − baseAddr），所有块共用
  • 缝隙跳过：文件之间的空隙不发送数据块
  • 完成判定 data_pos + data_len == full_length 由最大偏移文件的最后一块满足，下载器才执行 AUTORESET / 清理 VDDQ/EFUSECLK
  • slice_pos 分离（v3.1 修复）：命令字段 data_pos 为相对头部偏移（含文件地址），数据切片必须用文件内偏移 pos（hercules_cmd_flash_write 第 8 参 slice_pos，未传则默认 data_pos 兼容单文件）

10 · 浏览器与部署（Q3 详解）

结论：量产网页必须运行在 Chrome 或 Edge（Chromium 内核）上，且必须通过 HTTPS 或 localhost 访问。
为什么必须 Chrome/Edge？
  • 量产工具依赖 WebUSB API（与 Vllink 通讯）——只有 Chrome / Edge / Opera 支持
  • Firefox 不支持 WebUSB；Safari 仅 macOS 14+ 部分支持 → 无法用于量产
  • 自动配置载入依赖 File System Access API —— 同样仅 Chromium 支持
  • 所以"锁定 Chrome/Edge"是硬性要求，不是可选优化
为什么必须 HTTPS / localhost？
  • WebUSB 与 File System Access 都是安全上下文专属 API（Secure Context）
  • 产线部署推荐：本机 localhost + 桌面快捷方式（免服务器）
  • 或局域网内 HTTPS 服务器（如 nginx + 自签证书），多工位共享同一页面
推荐的产线部署形态（三选一）：
  • ① 单机 localhost：网页文件放本机，浏览器打开 http://localhost/web_program_hercules/index.html，固定工位使用
  • ② 局域网 HTTPS：一台内网服务器托管页面 + 自签证书，多台工位 PC 浏览器访问（File System Access 仍按各 PC 本地授权）
  • ③ 生产用 kiosk：Chrome 全屏 kiosk 模式，屏蔽地址栏/右键，防止误操作
